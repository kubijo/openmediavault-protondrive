# Dependency reporting and audits

Use the pinned tooling from the [README](../README.md); no local nix-tools checkout is required.

```sh
just outdated
just outdated --json
just audit
just audit --in-clanker
```

Both commands are Nix apps; Just only forwards arguments. Neither updates pins, lockfiles, dependencies or credentials.
Review the report before choosing upgrades. Network and registry failures are errors, never an "up-to-date" result.

## Version report

`outdated` compares the host Nix client, effective Nix tooling versions, GitHub flake inputs, all locked PyPI packages,
workflow action tags, Ubuntu runner releases, Proton CLI and Debian test images with their upstream metadata. It reads
`flake.lock`, `uv.lock`, workflow YAML and `config/sources.json`; the effective tool inventory is generated by Nix. The
report distinguishes committed flake pins from a local nix-tools override. Private repositories require GitHub CLI
authentication or `GH_TOKEN`; public requests also use the CLI's credentials when available.

States include `up-to-date`, `outdated`, `ahead` (a newer snapshot), `pinned` (an explicit upstream source revision),
`compatibility-pinned`, `blocked`, and `error`. Debian 12 / OMV 7 / Python 3.11 remain the NAS compatibility target; the
CLI's baseline CPU build is intentional. Those reasons are printed rather than silently hiding older versions. PyPI
results report upstream releases; resolver compatibility must still be checked before upgrading.

The final line gives an aggregate state and counts. Exit status is **0** when no updates/problems were found, **1** for
outdated components, and **2** for blocked, unknown or failed lookups. A blocked/error result still includes every
successful lookup. Explicit source pins are reported for review but are not treated as automatic upgrade candidates.

## Security and dependency audit

`infra/nix/maintenance.nix` defines the tools, commands and finding exit codes:

- `uv lock --check --offline`: manifest/lock consistency.
- `uv audit --locked`: Python vulnerability and adverse-project advisories from OSV.
- `deptry`: unused and undeclared Python dependencies.
- `gitleaks`: all available Git history, the working tree, and staged changes, with secret redaction.

Every step runs even if an earlier step fails. The final state is `PASSED`, `FAILED` (exit **1**, findings), or `ERROR`
(exit **2**, a tool could not complete). An unborn repository explicitly skips history scanning; it still scans the
working tree and index. CI fetches full history before auditing. Rust-specific tools are not applicable to this project.
The Python advisory scan does not claim coverage of embedded vendor libraries or the NAS's Debian packages.

## Console policy

All repository tooling shares `tools/console.py`. Human reports use Rich tables grouped by domain, with alternating row
backgrounds, column separators, and a final summary. Tables fit their contents, capped at 120 columns. The outdated
reporter collects domains in parallel and prints each completed section immediately. Human terminals show pending
sections with transient spinners; agents, dumb terminals, pipes, and no-colour mode never animate. Agent reports are
terse ASCII with the final state at the end; JSON is emitted once collection finishes. Detection checks the presence of
`CLAUDECODE`, `CURSOR_AGENT`, `GEMINI_CLI`, `CODEX_THREAD_ID`, `OPENCODE`, `IN_CLANKER`, or `in-clanker`, including
empty values.

`FORCE_COLOR=1` enables Rich with colour even through a pipe or automatic agent detection. `FORCE_COLOR=0` or explicit
`--in-clanker` selects plain output. `NO_COLOR` (including empty), `TERM=dumb`, and `--no-color` always disable ANSI.
`--json` includes component domains and complete diagnostics. Agent text shows only the final 20 diagnostic lines for a
noisy failure; JSON preserves the complete captured diagnostics. Arbitrary messages are rendered literally, not
interpreted as Rich markup. Captured tools have colour disabled through their environment and tool-specific flags.

Offline regression tests run through `just test` and Nix validation. They cover colour precedence, agent detection,
literal markup, release filtering, lookup failures, source metadata selection, aggregate results, and an actual Gitleaks
scan that rejects and redacts a generated test token.
